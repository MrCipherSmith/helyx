# Module bot

Version: 1.0.0
Type: component
Status: enriched

## Summary

Telegram frontend of the Helyx system. Receives all Telegram updates (text, media, commands, callback queries, poll answers), authenticates via access guard, routes to the appropriate backend (Claude Code CLI sessions or standalone Claude API), and streams responses back to Telegram. Acts as the bridge between the user's Telegram interface and the underlying session/memory/LLM infrastructure.

## Responsibility

Owns the entire Telegram user-facing layer. Handles 23+ commands across session management, project control, memory operations, monitoring, and system administration. Implements multi-step command flows via a pending-input pattern, inline tool/skill launchers with argument collection, permission approval callbacks (Allow/Deny/Always-Allow), curator action approval, and agent-created skill approval (save/reject/edit-name). Provides a streaming response experience with incremental edits, typing indicators, HTML formatting, and continuation chunks. Manages dual-mode operation: CLI mode (messages routed via `message_queue` DB table to tmux-based Claude Code sessions) and standalone mode (direct Claude API with per-topic sequential queue). Supports voice message pipeline (download → transcribe → queue with progress), image vision via Claude API, session switching with context briefing, and text-to-speech attachment.
