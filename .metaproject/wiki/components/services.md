# Module services

Version: 1.0.0

## Summary

Service layer — facades that encapsulate database operations and business logic behind a clean API for bot commands and MCP endpoints. Provides seven singleton services: Session, Project, Permission, Forum, Message, Memory, and Summarization services.

## Responsibility

Owns the database-facing business logic layer. Each service wraps one domain area behind an async class with a singleton export, providing a simplified API for consumers in `bot/commands/` and `mcp/`. Follows a consistent pattern: class + singleton + barrel re-export.

- **SessionService** — CRUD for Claude Code sessions, session-to-chat affinity, activity tracking.
- **ProjectService** — Project CRUD, lifecycle (start/stop via admin command queue), session-to-project linking, restart enqueue.
- **PermissionService** — Permission request state machine (pending→approved/rejected/expired), stale expiry on startup.
- **ForumService** — Telegram Forum topic management: setup, sync, orphan cleanup, topic creation per project with color rotation.
- **MessageService** — Short-term message storage delegation, message queue for injecting content into running sessions.
- **MemoryService** — Thin facade over long-term memory recall/store/list.
- **SummarizationService** — Thin facade over summarization: idle timer, overflow check, force summarize, disconnect save, project knowledge extraction.
